# День 0 · 21.10.2026 · разминка

## Железо

- Tesla T4 (Google Colab): 8.1 TFLOPS FP32, 320 GB/s HBM. CUDA / torch — см. ноутбук.

## Что сделал

- Первое ядро на Numba CUDA: map `out[i] = a[i] + 10` на 10⁷ float32 (`first_kernel.ipynb`).
- Сравнил с `torch.add`.

## Замеры

| Реализация | Время | Эффективная пропускная способность |
|---|---|---|
| torch.add, среднее из 100 | 0.349 ms | 230 GB/s |
| Numba map, один запуск | 0.509 ms | ~157 GB/s |

Numba — один запуск без усреднения, цифра зашумлена launch overhead'ом; переснять циклом из 100.

## Roofline

- Данные: 10⁷ float32 = 40 МБ на массив. Map читает один и пишет один → 80 МБ трафика, 8 байт на элемент.
- Работа: 1 FLOP на элемент → arithmetic intensity AI = 1/8 FLOP/byte.
- Потолок: P_max = min(8.1 TFLOPS, 320 GB/s × 0.125 FLOP/B) = **40 GFLOP/s** — ядро memory-bound с запасом в 200×.
- Минимальное время: 80 МБ / 320 GB/s = **0.25 ms**.
- Достигнуто: torch 0.35 ms → **71% roofline**; Numba 0.51 ms → ~49% (но см. оговорку про замер).

## Ошибки дня

1. `blocks = (a.size + threads - 1)` без `// threads` → 2.56 млрд потоков вместо 10⁷, 99.6% сразу отсекались guard'ом.
2. Замер одного запуска делился на 100 → «0.215 ms» вместо реальных 21.5 ms. Две ошибки маскировали друг друга: кривая сетка выглядела быстрой из-за кривого замера.

Урок: сначала убедиться, что замер честный, потом верить числам.
